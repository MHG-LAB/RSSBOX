【A股分钟级高频数据完全手册 #06】北交所分钟级数据接口：京市股票Pro版最新分时

【A股分钟级高频数据完全手册 #06】北交所分钟级数据接口：京市股票Pro版最新分时

系列：《A股分钟级高频数据完全手册》｜连载项目 · 纯 GET 取数 · 仅依赖 requests · Pro 版分钟级高频

① 你将得到什么

北交所（京市，代码 .BJ）是容易被忽略但弹性不小的市场。它的 Pro 版分钟数据走 /bj/pro/latest/{code}.BJ/1/n，结构和沪深一致，只是前缀换成 /bj/、后缀 .BJ。本篇把京市 Pro 最新分时拉通，并提示京市流动性/字段与沪深的差异。

本篇产出：用 /bj/pro/latest/{code}.BJ/1/n 拉取北交所股票最近的 N 条 Pro 版 1 分钟分时，解析字段并做统计，纳入多市场分钟数据底座。

读完这篇，你应当能独立把本篇端点数据拉下来、落本地，并跑出一份可用的加工分析表。

② 取数约定

一个端点拉数据，返回里字段名可能中英文混用（不同接口版本、不同数据源习惯不同）。演示用 你的token 占位，代码里 MOCK=True 时回放演示数据，接真实 token 把 MOCK 改成 False 即可，无需改动其他逻辑。

所有请求走 https://api.zhituapi.com + ?token=，纯 GET、仅依赖 requests，不依赖任何付费 SDK。字段口径以接口实际返回为准，本文用 _hit_key 做了大小写/中英文容错；落地前建议先用 print(r[0].keys()) 核对一次你账号下的真实字段名。

落地建议：把每天拉到的数据按 代码 + 日期 做主键写入本地 SQLite/CSV，避免重复插入；历史回看靠本地累积，而非反复调接口。本篇示例代码已包含字段容错映射与本地加工函数，你只需把 print 替换为写入语句。

端点用途

返回结构为 JSON 数组（或含数组字段的对象），每条记录即一根分钟 bar / 一笔明细；字段映射函数已按上述字段做容错映射，直接复用即可。

⑥ 编号坑

  • 北交所代码后缀是 .BJ、接口前缀是 /bj/，和沪深 (.SZ/.SH、/hs /hz) 完全不同，套用会 404。
  • 京市股票流动性相对沪深低，成交量量级小，单位与阈值不要照搬沪深经验。
  • 部分京市票盘口较薄，1 分钟 bar 可能出现零成交或跳价，清洗时要识别异常。
  • Pro 权限同样适用于北交所，确认账号已开通 Pro 再批量拉。
  • 字段（o/open、v/vol）与前两市一致，_hit_key 容错复用。
  • 时间/时区/复权规则同沪深，统一处理即可。
  • MOCK 演示数据虚构，实盘核对真实量级。
  • 额度：纳入多市场后总量增大，规划好并发与限速。
