卫星信号模拟器里的四个坐标转换公式

卫星信号模拟器里的四个坐标转换公式

一套卫星信号模拟器里，坐标转换看起来是"边角料"，但其实贯穿始终：算仰角要用它、算电离层穿刺点要用它、生成用户轨迹要用它、上位机显示经纬高也要用它。这篇把工程里真正在用的四个转换函数拆开讲清楚。

0. 四个函数各干什么

函数方向用在模拟器哪里
xyz2llhECEF 直角坐标 → 经纬高上位机显示、反解用户位置
LlhToXyz经纬高 → ECEF 直角坐标场景文件里给经纬高时转成直角坐标
xyz2enuECEF → 东北天(ENU)算仰角、电离层/对流层误差
enu2xyz东北天 → ECEF用户轨迹生成（ENU 速度/位移 → ECEF）

坐标系约定都是 WGS-84：长半轴 a=6378137.0 m，短半轴 b=6356752.3142 m。

1. ECEF → 经纬高：xyz2llh

这是四个里最"重"的一个——反解本身没有初等闭式，工程上用的是先解中间量再一步到位的方法（经典来自 Kaplan《Understanding GPS》）：

// 输入 xyz[3]（米），输出 llh[3] = {纬度, 经度, 高度}，纬度/经度为弧度
void xyz2llh(const double xyz[3], double llh[3])
{
    const double a = 6378137.0, b = 6356752.3142;
    const double e2 = 1.0 - (b*b)/(a*a);        // 第一偏心率平方
    const double ep = sqrt((a*a - b*b)/(b*b));  // 第二偏心率 e' = e·a/b


<span class="hljs-type">double</span> x = xyz[<span class="hljs-number">0</span>], y = xyz[<span class="hljs-number">1</span>], z = xyz[<span class="hljs-number">2</span>];
<span class="hljs-type">double</span> r  = <span class="hljs-built_in">sqrt</span>(x*x + y*y);                <span class="hljs-comment">// 到地轴的投影距离</span>
<span class="hljs-type">double</span> r2 = r*r, z2 = z*z;

<span class="hljs-type">double</span> E2 = a*a - b*b;
<span class="hljs-type">double</span> F  = <span class="hljs-number">54</span>*b*b*z2;
<span class="hljs-type">double</span> G  = r2 + (<span class="hljs-number">1</span>-e2)*z2 - e2*E2;

<span class="hljs-type">double</span> c  = (e2*e2*F*r2) / (G*G*G);
<span class="hljs-type">double</span> s  = cbrt(<span class="hljs-number">1</span> + c + <span class="hljs-built_in">sqrt</span>(c*c + <span class="hljs-number">2</span>*c));      <span class="hljs-comment">// (…) 的立方根</span>
<span class="hljs-type">double</span> P  = F / (<span class="hljs-number">3</span>*(s + <span class="hljs-number">1</span>/s + <span class="hljs-number">1</span>)*(s + <span class="hljs-number">1</span>/s + <span class="hljs-number">1</span>)*G*G);
<span class="hljs-type">double</span> Q  = <span class="hljs-built_in">sqrt</span>(<span class="hljs-number">1</span> + <span class="hljs-number">2</span>*e2*e2*P);

<span class="hljs-type">double</span> ro = -(P*e2*r)/(<span class="hljs-number">1</span>+Q)
          + <span class="hljs-built_in">sqrt</span>( (a*a/<span class="hljs-number">2</span>)*(<span class="hljs-number">1</span> + <span class="hljs-number">1</span>/Q)
                  - (P*(<span class="hljs-number">1</span>-e2)*z2)/(Q*(<span class="hljs-number">1</span>+Q))
                  - P*r2/<span class="hljs-number">2</span> );
<span class="hljs-type">double</span> tmp = (r - e2*ro)*(r - e2*ro);
<span class="hljs-type">double</span> U   = <span class="hljs-built_in">sqrt</span>(tmp + z2);
<span class="hljs-type">double</span> V   = <span class="hljs-built_in">sqrt</span>(tmp + (<span class="hljs-number">1</span>-e2)*z2);
<span class="hljs-type">double</span> zo  = (b*b*z)/(a*V);

llh[<span class="hljs-number">2</span>] = U*(<span class="hljs-number">1</span> - b*b/(a*V));                       <span class="hljs-comment">// 高度</span>
llh[<span class="hljs-number">0</span>] = <span class="hljs-built_in">atan</span>((z + ep*ep*zo)/r);                  <span class="hljs-comment">// 纬度</span>
llh[<span class="hljs-number">1</span>] = <span class="hljs-built_in">atan2</span>(y, x);                             <span class="hljs-comment">// 经度</span>



&#125;

要点：经度直接 atan2(y,x)；纬度和高度靠中间量 ro（地心到大地纬面法线交点的近似距离）一次性解出。这个写法避免了迭代，在接收机和模拟器里都很常用。

2. 经纬高 → ECEF：LlhToXyz

这个有标准闭式，工程里写法略绕，但等价于大家熟悉的 N·cosφ·cosλ 形式：

void LlhToXyz(const double llh[3], double xyz[3])
{
    const double a = 6378137.0, b = 6356752.3142;
    const double e2   = 1.0 - (b*b)/(a*a);
    const double ome2 = 1.0 - e2;                 // 1 - e²


<span class="hljs-type">double</span> lat = llh[<span class="hljs-number">0</span>], lon = llh[<span class="hljs-number">1</span>], h = llh[<span class="hljs-number">2</span>];
<span class="hljs-type">double</span> clat = <span class="hljs-built_in">cos</span>(lat), slat = <span class="hljs-built_in">sin</span>(lat);
<span class="hljs-type">double</span> clon = <span class="hljs-built_in">cos</span>(lon), slon = <span class="hljs-built_in">sin</span>(lon);

<span class="hljs-type">double</span> tlat2 = (slat*slat)/(clat*clat);       <span class="hljs-comment">// tan²φ</span>
<span class="hljs-type">double</span> d     = <span class="hljs-built_in">sqrt</span>(e2)*slat;                 <span class="hljs-comment">// e·sinφ</span>

xyz[<span class="hljs-number">0</span>] = a*clon/<span class="hljs-built_in">sqrt</span>(<span class="hljs-number">1</span> + ome2*tlat2) + h*clon*clat;
xyz[<span class="hljs-number">1</span>] = a*slon/<span class="hljs-built_in">sqrt</span>(<span class="hljs-number">1</span> + ome2*tlat2) + h*slon*clat;
xyz[<span class="hljs-number">2</span>] = a*ome2*slat/<span class="hljs-built_in">sqrt</span>(<span class="hljs-number">1</span> - d*d) + h*slat;



&#125;

等价性说明（这也是个不错的自查题）：

1 + ome2·tan²φ = (cos²φ + (1−e²)sin²φ)/cos²φ = (1 − e²sin²φ)/cos²φ

所以 a/sqrt(1 + ome2·tan²φ) = a·cosφ/sqrt(1−e²sin²φ) = N·cosφ，其中 N 是卯酉圈曲率半径。代入就是教科书形式 x = (N+h)cosφcosλ，z = (N(1−e²)+h)sinφ。工程写法只是把 N 展开成了 tan²φ 和 d² 的形式，数值上更稳。

3. ECEF → 东北天：xyz2enu

以用户位置为原点建 ENU 坐标系，核心是一个旋转矩阵（来自 Leick《GPS Satellite Surveying》）：

// 输入：xyz=目标点(卫星)ECEF，orgxyz=原点(用户)ECEF；输出 enu[3]={东,北,天}
void xyz2enu(const double xyz[3], const double orgxyz[3], double enu[3])
{
    double dx = xyz[0]-orgxyz[0], dy = xyz[1]-orgxyz[1], dz = xyz[2]-orgxyz[2];

xyz2llh(orgxyz, llh);                 <span class="hljs-comment">// 先反解用户经纬度</span>
<span class="hljs-type">double</span> phi = llh[<span class="hljs-number">0</span>], lam = llh[<span class="hljs-number">1</span>];    <span class="hljs-comment">// 纬度 φ、经度 λ</span>

enu[<span class="hljs-number">0</span>] = -<span class="hljs-built_in">sin</span>(lam)*dx + <span class="hljs-built_in">cos</span>(lam)*dy;
enu[<span class="hljs-number">1</span>] = -<span class="hljs-built_in">sin</span>(phi)*<span class="hljs-built_in">cos</span>(lam)*dx - <span class="hljs-built_in">sin</span>(phi)*<span class="hljs-built_in">sin</span>(lam)*dy + <span class="hljs-built_in">cos</span>(phi)*dz;
enu[<span class="hljs-number">2</span>] =  <span class="hljs-built_in">cos</span>(phi)*<span class="hljs-built_in">cos</span>(lam)*dx + <span class="hljs-built_in">cos</span>(phi)*<span class="hljs-built_in">sin</span>(lam)*dy + <span class="hljs-built_in">sin</span>(phi)*dz;



&#125;

有了 ENU，仰角就是 atan2(enu[2], sqrt(enu[0]²+enu[1]²))，方位角是 atan2(enu[0], enu[1])。电离层穿刺点、对流层映射函数也都从这里接着算。

4. 东北天 → ECEF：enu2xyz（这篇最有意思的一处）

ENU→ECEF 严格写法是上面旋转矩阵的转置：

// 严格版（旋转矩阵的逆）
dx = -sin(lam)*e - sin(phi)*cos(lam)*n + cos(phi)*cos(lam)*u;
dy =  cos(lam)*e - sin(phi)*sin(lam)*n + cos(phi)*sin(lam)*u;
dz =                 cos(phi)*n         + sin(phi)*u;

但你工程里实际启用的是一个小角度近似版：

// 近似版（wcy-20210318，工程里在用）
void enu2xyz(const double enu[3], const double orgxyz[3], double xyz[3])
{
    double llh[3];
    xyz2llh(orgxyz, llh);
    double phi = llh[0], lam = llh[1], h = llh[2];


<span class="hljs-comment">// 1° ≈ 110 km：把东北位移近似成经纬度增量</span>
<span class="hljs-type">double</span> d_lam = enu[<span class="hljs-number">0</span>] / <span class="hljs-number">110000.0</span> * (PI/<span class="hljs-number">180</span>) / <span class="hljs-built_in">cos</span>(phi);  <span class="hljs-comment">// 东 → 经度差</span>
<span class="hljs-type">double</span> d_phi = enu[<span class="hljs-number">1</span>] / <span class="hljs-number">110000.0</span> * (PI/<span class="hljs-number">180</span>);              <span class="hljs-comment">// 北 → 纬度差</span>

<span class="hljs-type">double</span> llh2[<span class="hljs-number">3</span>];
llh2[<span class="hljs-number">0</span>] = phi + d_phi;
llh2[<span class="hljs-number">1</span>] = lam + d_lam;
llh2[<span class="hljs-number">2</span>] = h   + enu[<span class="hljs-number">2</span>];          <span class="hljs-comment">// 天向直接加高度</span>

LlhToXyz(llh2, xyz);



&#125;

为什么放着严格的旋转矩阵不用，用这个近似？ 注释里写得很实在："解决长时间运行高度不正确问题"。工程背景是——用户轨迹是长时间积分生成的，每一步的 ENU 增量都很小（米级），而严格的旋转矩阵版本在长时间累积、大数值坐标下反而会因浮点精度和模型细节（绕法线 vs 绕球面）引入高度漂移。小角度近似在"每步只走几米"这个前提下足够准（误差二阶小量），而且数值稳定。

但要记住它的适用边界：只适合小位移增量。如果要一次性换算一个大位移（比如几公里的 ENU 偏移），必须用旋转矩阵版，否则误差会明显。
