App+1｜Agora：开源、易用、好用，给 Android 用户的 LLM 聊天工具


我是大语言模型（LLM）的日常使用者，同时也是不止步于现有解决方案的「极客」。长期以来，Kimi、DeepSeek 等头部厂商提供的客户端都能满足我日常的聊天需求。但后来我了解到小米 MiMo v2.6 系列模型拥有同样强大的表现，还没有折磨人的「5小时限额」1，就决定试试。

结果这一试就让我爱上了 MiMo，享受 MiMo 的性能、回答质量与 Agent 表现，当然也爱上了（对当时的我来说）很新却很实用的方式——使用 API 远程调用大模型。

API 调用大模型作为一种相对成熟的用法，也催生了一套强大、稳定的 LLM 生态。对我来说，最大的意义莫过于以此实现属于自己的 LLM 聊天体验：选择一款支持自定义配置的开源聊天工具，在聊天客户端中配置不同厂商的 API，就可以在同一个 App 中使用多家厂商的模型，还可以让你更好地掌控聊天过程和相关数据。这是与各大厂商 AI 聊天应用相比截然不同的体验，还能弥补 MiMo 等部分厂商未提供官方聊天工具的不足2。

而在桌面端，成熟、支持 BYOK3 的开源聊天工具早已有之：ChatBox、Jan，开箱即用，还跨平台。支持 BYOK 的产品往往兼容 OpenAI、Anthropic 的 API，只要厂商提供与之相兼容的 API 接口，就可以轻松连接。

然而在 Android 端这一块几乎是空白，仿佛除了厂商自家的聊天应用外，就没有别的选择了。能找到的开源产品，一度只有 oxproxion、GPTMobile 这种跟特定厂商牢牢绑定的软件4。我不甘心止步于此，在 F-Droid 商店中更换关键词反复寻找、对比（吐槽一下 F-Droid 机械呆板的检索功能），最终找到了这款隐藏的宝藏软件 ——独立开发者 Newo Ether 的 Agora。

Agora 支持 BYOK 方式接入各类厂商的 API，只需简单配置即可随时随地在手机上跟你喜欢的大模型聊天。更重要的是，它拥有现代化、易用性高的界面，只要你用过 Kimi、豆包等主流 AI 助手 App，就能很快适应并上手 Agora 的逻辑，几乎不用从头再学。

依我看，或许在当下，它就是 Android 平台 BYOK 开源聊天工具的最优解。

熟悉的界面，熟悉的上手逻辑

对一款面向大众用户的软件来说，界面易用性可以说是很重要的。如果一款新软件已经有很多同品类竞品，开发者在设计 UI 时就有必要以这些「竞品」软件的共同操作逻辑为立足点。如此一来，熟悉「竞品」软件的用户就能很快上手你的软件。

毕竟，接触新的软件，还要从头学一遍的话，那是真的能劝退很多新人。5

就像 Windows 深入人心的「开始」菜单和任务栏那样，AI 聊天软件本身也有让人们熟悉的共同 UI 逻辑。如果你手机上有多款商业的 AI 聊天客户端，你会发现它们的界面基本大同小异：

  • 打开主界面就是对话界面，可以直接在文本框中输入消息（提示词）
  • 对话界面简洁，只有顶栏、底部文本框，以及中间占据主要空间的对话显示
  • 文本框常常附带一个「+」按钮，可以上传附件
  • 顶栏的汉堡按钮可以打开对话列表，还可以从顶栏选择模型
  • 文本框为空时，上方会出现一排工具按钮，可以调用厂商的特色功能

看看 Kimi 和豆包的界面，是不是长得很像？那么，咱们再来看看 Agora 的界面，这个布局和操作风格是不是更加给你一种「他乡遇故知」的感觉？

相信这样的布局能让你也快速上手。正是因为 Agora 采用的 UI 逻辑经过了各大知名 AI 厂商的长期验证，会用 ChatGPT、豆包、Kimi 等 App 的朋友，初次接触 Agora 也完全不必再攀登另外一座「学习曲线」的山峰，为这款新软件付出额外的学习成本。

Agora 不会劝退你。

使用前的第一步：配置 LLM 提供商与模型

说是容易上手，不过，在打开 Agora 主界面之后先别急着发消息。

Agora 并不是开箱即用的，作为一款不绑定任何厂商的 LLM 聊天客户端，你需要手动配置 LLM 提供商与模型。

设置提供商

只需点击 UI 左上角的「Agora」按钮，打开「对话」面板，然后依次点击「设置 -> 提供商」，即可进入配置提供商的界面。面向不同用户的需求，Agora 支持三类不同的提供商：

a) 内置提供商

Agora 内置了 8 家主流提供商的接入方式，既包括 Google、OpenAI、Anthropic、DeepSeek 这样的主流厂商，也包括第三方的 LLM 服务平台——Open Router。开发团队为这些平台做了良好的适配，无需配置过多的参数，只需添加 API Key 即可，剩下的工作由 Agora 来处理就好。

相信一些读者就用着至少其中一家的服务，点击相应的提供商并添加 API Key，你会发现 Agora 支持添加多个 API Key。这里考虑的是多用户、多账号、多环境的需求（例如，企业账号与个人账号区分开来），你可以添加不止一个 API Key 然后手动切换，日后随时可以增删和修改。为了便于区分，Agora 还允许你为 API Key 指定「名称」（相当于备注），这样可以防止搞混，比人工分辨那一长串 API Key 要方便多了。

需要注意的是，Ollama 与其他提供商不同，作为一个本地部署的平台，你需要在 Ollama 提供商的设置界面中确认「基础 URL」（也就是 API URL）是否填写正确。若要使用 Ollama，我个人建议你优先考虑在局域网中部署，这样可以节省设备资源，具体教程可以参阅官方文档。

b) 自定义提供商

Agora 自带的提供商显然不足以覆盖所有优秀的厂商，我常用的小米 MiMo 就没有提供。

幸运的是，得益于 OpenAI 的巨大影响力，OpenAI 这家 AI 巨头的 API 规范（API schema）已经成为了业内的事实标准，因此无论是 MiMo 等大模型厂商，还是 llama.cpp 这样的基础设施，都至少提供了兼容 OpenAI 的服务端。与此同时，Anthropic 和 Google 的 API 规范同样具有影响力，因此部分厂商也提供兼容。

Agora 作为 BYOK 的聊天工具，必然提供了自定义提供商的选项，可以让你使用兼容上述三家巨头 API 的提供商。在「提供商」界面里往下滑，你就能见到「自定义提供商」的栏目，如下图所示。

点击「添加提供商」，选择提供商的兼容 API 类型（OpenAI / Anthropic / Google），然后填入提供商给你的地址与 API Key，即可完成配置。你同样可以为每个提供商添加不止一个 API Key。

本地部署的 llama.cpp，可以借助「自定义提供商」在 Agora 中使用，这同时适用于局域网与手机上的部署6。只需把提供商的地址设为 llama.cpp 服务器（llama-serve）的地址即可。在接下来的步骤中，Agora 就可以为 llama.cpp 用户带来绝佳的、不亚于大厂 App 的移动端 LLM 聊天体验。

c) 本地模型

除了运行在线模型，Agora 还支持导入 GGUF 格式的本地模型，由其内置的 llama.cpp 运行。

对于没有条件折腾本地部署模型的用户来说，这一功能非常有实用价值，不用折腾 llama.cpp 等软件环境，只需导入模型即可开启本地 AI 大模型体验，甚至还可以导入 MMPROJ 模型（多模态投影文件），为支持多模态的模型（如 Gemma4）开启多模态功能，启用图像、音频识别等高级特性。

不过，Agora 的本地模型运行能力非常不尽如人意，依我看尚未达到可以广泛适用的水平。具体我会在下文专章讲解。

别忘了启用模型

在完成提供商的配置后，你还需要启用模型才能使用。这就是本地 AI 聊天工具常见的「两步走」设置方式：提供商设置与模型设置是分离的。

在 Agora 的「设置」界面中，点击「模型」，打开模型管理界面。此时，在下方「已获取模型」这一栏中，会列出所有已添加提供商的模型，按提供商分类。你只需在这里点一下「从所有提供商同步」，拉取模型列表，然后点开你要使用的提供商，勾选你要用于聊天的模型即可。

以 MiMo 为例，我添加了 MiMo 的按量计费（取名为MiMo On Demand）与 Token Plan 这两个提供商7。点开「MiMo On Demand」就可以看到小米提供的 7 个模型，勾选「MiMo V2.6 Flash」与「MiMo v2.6 Pro」，即可启用这两个最重要的聊天模型。

这一「按需启用」的模式，可以有效防止误选 Agora 不支持的模型（例如 TTS、ASR 等语音模型）。还可以把费率偏高的模型排除在外，防止聊天的时候不慎选到「刺客」，比如 Claude Opus / Fable 系列8或 MiMo v2.6 Pro Ultraspeed9。

设置完成后，就可以在聊天界面中直接选模型了，模型选择器位于聊天输入框底部（「+」按钮右侧）。

实际使用体验：以 MiMo 为例

作为 MiMo 的用户，找到 Agora 让我如获至宝。截至发稿时，MiMo 只提供了桌面应用，没有提供手机应用，然而我又有随时随地使用 MiMo 的刚需，Agora 正好填补了这个空白。

MiMo 官方提供了兼容 OpenAI 的API，进行简单配置后，就可以马上开启聊天了。

不输商业 AI 客户端的聊天体验

我就以这样一个问题开始：「给出华硕天选的两款机型，让 MiMo 评估哪款机器更胜任」。

我在 Agora 里输入提问内容（提示词），还附上了两张淘宝截图。点击「发送」按钮之后，Agora 快速响应，飞快输出 MiMo 的思考内容，思考一段时间之后给出了结果，还自动为会话生成了标题。整个使用过程丝滑流畅，丝毫没有卡顿，可见 Agora 的性能优化非常到位（当然了，提供商 MiMo 本身的响应也很迅速）。

界面设计的细节上 Agora 也是深得我心。聊天界面的布局与主流 LLM 客户端保持一致，己方发言的绿色气泡，以及模型输出结果的完整 Markdown 版面，给我的感觉尤为熟悉亲切。输出内容版面上，开发者把行距、表格大小、字号等视觉要素调整的恰到好处，读起来赏心悦目，让翻看对话记录成为一种享受。

Agora 默认也会在模型思考过程中，把思考内容最新的一行实时展示出来，让我实时了解模型思考的简况。还有一个让我很爽的点是触觉反馈，Agora 在完成思考、输出正式答案的过程中会有振动反馈，随着文字输出手机也会不断轻轻振动，就像 LLM 在敲键盘打字一样，让你「摸得着」Agora 的回答节奏。Agora 用触觉反馈告诉你「我在回答」，配合流畅的屏幕输出，更加「活」起来。如果你不习惯触觉反馈，可以在「设置 -> 外观」中关闭。

从上面这个对话不难得知，Agora 天生对多模态的模型有完备的支持。如果你选择的模型 API 支持，在聊天中添加的图片都能正常发给模型解析。它也内置了相机调用和媒体文件发送。从这些交互细节上来说，Agora 是完全不输大厂同形态商业应用的。

基于本地沙箱的附件解析

附件方面，Agora 原生支持的文件格式包括纯文本（如 TXT、Markdown 等）和 PDF。在上传PDF 的时候，可以选择上传哪些页数。

而对于其他格式的附件（如 Word 文档、Excel 表格）Agora 不提供原生支持，完全依赖内置的 Linux 隔离沙箱环境——「Local Sandbox」（本地沙箱）。例如我想上传 Word 文档，刚开始会提示格式不支持，要启用「Local Sandbox」才能解析文件。这时只用打开「设置 -> 终端」，打开「本地沙箱」开关，随后点击「沙箱管理 -> 安装」下载沙箱环境。

Agora 的沙箱基于 Alpine Linux，一款轻量而强大的 Linux 发行版。启用沙箱后，Agora 就完全解锁了各种文件类型的支持，仿佛打通了「任督二脉」。遇到原生不支持的附件格式，它会上传到沙箱里交给 LLM 自行尝试解析，比如对于 Word 文档，我选用的 MiMo v2.6 Flash 会尝试 Python、unzip 等多种工具，在沙箱未安装 Python 的时候就会使用 unzip 解压文档，然后从文档的 XML 数据里提取正文内容10。

在「沙箱管理」界面中，你可以为沙箱环境安装各种软件包。开发者把常用的软件包都列在了「快速安装」栏目里，点击即可立即安装。对于新手来说，得益于 Python 庞大的第三方库，仅安装 Python 就已经能解析大部分常见的文档格式。而对于专家级用户，你可以在「沙箱管理」里自行输入你想安装的 Alpine 软件包名，让 Agora 帮你安装自定义软件包，随后 LLM 就可以按需调用相关软件来解析特殊格式。11

需要注意的是，对于非原生支持的文件，能否正常解析，全靠模型调用工具解决问题的能力（也就是 Agent 能力）。 模型需要自己判断文件格式，选择合适的工具、编写合适的终端命令，甚至需要编程。因此选择一款强大的、能胜任 Agent 的 LLM，也是用好 Agora 附件功能的关键。

最后，这个功能远远不止于解析附件。

熟悉近两年 Kimi、ChatGPT 与 Gemini 网页版的读者，或多或少都有这样的体验：在帮你做项目，或者解答一些有难度的问题时，它们会调用终端，运行命令或者自己编写的程序，从而能够解决纯靠文字和推理很难完成的各种复杂任务，极大拓展了能力边界。

Agora 的本地沙盒把这一强大特性也整合了进来，当你向 LLM 提出一些有挑战性的任务时，LLM 可以调用本地沙盒终端，调用其 Alpine Linux 环境下的各种强大工具，为你解决问题。举个例子，你可以直接在 Agora 里，让 LLM 为你编写一个 Python 项目，完成开发、调试、打包一条龙任务，体验与 Kimi 等商业 AI 网页版无异。

当然，如果你想让 Agora 完成更专业的任务，甚至可以利用本地沙盒的软件管理功能，在原版 Alpine Linux 强大的软件包阵容（只要软件支持你设备的架构，如 ARM64）里安装各种专业工具，进一步激发 LLM 解决问题的潜力。

开箱即用的 Web 搜索支持

回到刚才「对比华硕天选机型」的问题。让 AI 助手对比电脑配置，是一个需要即时联网搜索的工作。AI 工具能不能调用搜索引擎，这直接关系到回答是否可靠。

Agora 中的 MiMo 模型在必要的时候自动调用了搜索，让我得到了相对可靠的结果，这得益于 Agora 开箱即用的内置 Web 搜索工具（web_search），以及配套使用的 Web 抓取工具（web_fetch）。

Agora 的搜索工具可以在「设置」界面的「工具 -> 网页搜索」中配置。它默认支持 6 种搜索提供商，包括：

  • 免费的 DuckDuckGo
  • 需要提供 API Key 的 Brave、Tavily 等搜索引擎
  • 开源、支持本地部署的元搜索引擎12（meta-search engine）——SearXNG

实测 DuckDuckGo 已经能满足使用。对于日常问答、资料检索、事实核查等常见用途来说，输出的结果足够让 LLM 组织回答。如果搜索结果不够用，你还可以把搜索结果返回数量调大，最多支持 10 条结果。不过，对于国内用户来说，Agora 的搜索工具本身存在局限性：

  • 要顺畅使用 DuckDuckGo，离不开合适的网络接入环境，并且使用 DuckDuckGo 时可能触发反爬保护13（截至发稿时，该保护措施不是绝对严格的。实测 MiMo 可以在出错时重试搜索，通常多尝试就能成功）；
  • SearXNG 需要自己部署和调优，个人搭建需要使用 Docker，有一定的技术门槛；
  • 另外几索引擎需要注册或付费。

依我看，这几款提供商的客观限制，直接制约了 Agora 的「开箱即用」体验。如果 Agora 能像 Jan 那样接入 Exa 搜索引擎，或者是允许自行配置搜索 API，体验必能更上一层楼——Exa 有「管够」的每月免费额度，在国内也能顺畅连接。

分支对话

在与大模型对话时，如果我有了新的想法或见解要与大模型讨论，但担心接下来的提问会影响后续的对话内容，不想污染现有的上下文，这时就可以使用「分支对话」功能，在保留分支前上下文的前提下开启一个新对话。这一功能是 ChatGPT、Gemini 与 VS Code Copilot 的标配，现在 Agora 也为你带来了完整的分支对话体验。

Agora 直接把分支对话按钮放在 LLM 的每一个回答下方，作为一个一级功能按钮提供（没有把它收在「更多」菜单里）。创建分支对话之后，你会看到 Agora 开启了一个新会话，分支之前的上下文都整整齐齐地出现在会话中。原有的会话不变，你尽管放心在新会话里提问。

这个功能对我来说是刚需。我经常会跟大模型进行超长的对话，动辄几十轮，每一个新回答都可能影响后面的走向。比如，原本的对话聊的是对我工作时遇到的问题如何做决策，后来我又聊了最近状态不给力的问题，那么 LLM 在后续为工作出谋划策的时候，就有可能会把重点放在「让我本人调整状态」上，而不是去继续解决工作问题。14对于这种情况，我可以分支一个会话，在新会话里聊生活问题，而原本的会话则继续聊工作，降低话题干扰。

高级特性

除了最基础的聊天功能，Agora 还提供了一些非常高级的特性，助力高手们把 Agora 玩出花样，进一步迸发 LLM 的能力。这些特性都可以在「设置」界面里配置。接下来谈几个有代表性的。

Skill

Skill 可以按需调用可复用的各种指令，拓展模型的表现能力。原本 Skill 多用于 Claude Code、Codex、Cline 这样的 Agent 工具，Agora 把这一特性带到了手机聊天工具中，你可以把一系列常用的技能指令添加到其中，让 Agora 按需调用。

目前版本（v2.2.0）的 Agora 只支持从本地添加 Skill，它支持导入 Markdown 格式的 Skill，可以导入 Skill 作者们直接写好的 SKILL.md 文件（或者是你自己写的指令）。

⚠️ 注意：Agora 不能读取与 Skill 关联的其他文件15，因此如果关联的文件里有必不可少的内容，务必把它们全部复制到 SKILL.md 里。

对话搜索

Agora 的「对话搜索」为 LLM 赋予了检索既往对话的能力，让模型更懂你。它可以有以下妙用：

  • 你在对话过程中，可能希望模型能参考（或者基于）过往的对话来作出回答，以让它更人性化，同时免于让你手动输入冗长的背景资料。
  • 有些模型在回答的时候，也可能会倾向于看你过去的对话说了什么，从而得出更加贴合你情况的回答。
  • 再者，对于上下文窗口比较小的模型，你还可以在完成一组对话后，开启新对话，并让模型检索到上一个对话，从而间接「拓展」上下文的限制。

Agora 默认提供关键词检索16，并且允许你自行配置最大检索数量、相似度阈值和上下文字数，以让模型更好地检索你的会话。假如模型很难定位到你的对话记录，不妨放宽上面的这些参数。

实际使用过程中，并不是所有模型都会主动检索。因此，如果你要让 LLM 参考你过往的对话，最好明确要求模型去检索。可以参考下面这些提示词（包括但不限于）：

读取会话记录里关于_________的内容。（后面可以接着写你要让模型做的工作。）

列出所有关于_______的对话。 / 你能否检索过去的所有会话？（这两个提示词可以检验「对话搜索」是否可用。）

搜索会话记录，看看我之前说的__________。

读取标题为________的会话。

通常模型会根据你的输入自己尝试不同的关键字，只要关键词正确，往往最终都能正确命中。若模型一直检索不到内容，你可能要考虑放宽相似度阈值、上下文字数，或者直接换一个模型。

压缩会话与上下文窗口管理

每个大模型的上下文窗口都是有限的，超出上下文窗口就无法继续对话。Agora 内置了上下文压缩功能，当对话内容即将占满上下文窗口时，会对会话进行结构化的总结，从而腾出上下文窗口。

会话压缩本身也要调用大模型，Agora 默认有一套开箱即用的提示词来进行压缩，高级玩家可以点开「设置 -> 上下文」，把它改成效果更好的提示词并控制压缩阈值（上下文窗口用到哪个百分比就进行压缩）。

在上下文窗口的管理上，Agora 也提供了巧妙的视觉反馈：你可以用变暗的颜色来显示上下文窗口外的内容。每个模型在上下文压缩或超出范围后的表现都不一致，当你发现上下文超出窗口范围或压缩不当，导致会话质量下降、部分细节丢失时，你就可以追踪到那些「变暗」的内容，从而推知哪些内容被模型「丢掉」了。

我觉得这比某些「悄咪咪」压缩甚至直接丢弃上下文的 AI 助手强多了。

记忆管理

「记忆管理」可以自动将聊天中的内容保存为长期记忆，以便后续的 LLM 会话参考。如果你将 Agora 用作 AI 助手和工作、生活拍档，希望它能在每个对话中都能记住你的情况，不至于「失忆」，则这个功能很实用。

比如用 Agora 长期跟踪你的工作情况，每次对话都与工作相关，那么「记忆管理」就能让 Agora 实时记住你的情况，每次对话的时候就不用再把情况重新跟它说，它就能「懂你」。

不过我个人在使用 AI 助手的时候，每次都会涉及各自独立的话题，希望每次会话不会被既有的记忆干扰，得出「跑偏」的回答，所以我没有启用。假如说我之前吐槽某个工作任务，Agora 给我记下来了，结果下次让 Agora 出谋划策的时候，它突然想到我「当时吐槽过xxx」，于是后续给出的建议全部都以那一次的吐槽为背景，脱离我现在的真实情况。

综合来看，用不用该功能取决于你的个人习惯。

运行本地模型

在前文中我提到，Agora 除了支持 BYOK 接入 LLM 提供商，还支持运行 GGUF 格式的本地模型。只要设备硬件足够强、RAM 足够大，即可发挥本地模型的优势，没有网络也能推理。

我的手机是顶配的一加13，24GB RAM + 1TB 存储，比现在新机型顶配的 16GB RAM 容量还大（市售的手机几乎不再有这么大的 RAM 了），跑 8B 参数（Q8_0 量化）的大模型绰绰有余。因此我一开始对 Agora 的本地模型功能很有兴趣也很期待，结果实测下来被「泼了盆冷水」。

选择本地模型

手机等 Android 设备的 RAM 有限17，因此在选择模型时，务必先从小参数、低量化的模型开始测试。在我的一加13上，我选择了 Q8_0 量化的 8B 参数模型，大小控制在 10 GB 以内；要想再压缩容量的话就选更低一档的量化，例如 Q4_K_M、Q6_K 等规格。在本文中，我测试的是 Qwen3 8B 模型，Q8_0 量化，从 HuggingFace 下载（ggml-org/Qwen3-8B-GGUF）。

将模型保存到手机里，然后打开 Agora 的「设置 -> 提供商」，拉到最下面找到「本地模型」，点开之后点击「导入 GGUF 模型」。

随后就会进入「添加本地模型」界面。点击「聊天模型」一栏并并打开你本地的 GGUF 模型，Agora 就会把它复制一份到它的资料库中。然后依次配置以下参数：

  • 填写「模型 ID」（模型的唯一标识符），只允许使用小写字母、0～9 的数字、下划线和半角句点。
  • 填写「别名」（易于记忆的名字）。
  • 修改「上下文大小」（上下文窗口）。
  • 如果模型支持视觉输入（图像识别），还可以加载与其配套的 mmproj 文件（一般在 HuggingFace 中随模型一同发布）。

特别注意的是，上下文窗口初期不宜设置的太大，以默认值（16384）为宜，后续我们可以再调整。

开始测试

配置好的本地模型默认已经处于启用状态，回到聊天窗口里，我们就可以直接选用本地模型了。这里我做一个最简单的测试：输入「你好」，看看模型是否能正常工作。

不过在我的测试中，Agora 一直停留在这里不动，看似在加载模型、处理 Prompt，最终却停在这里好几分钟，没有给任何反馈，我只能对着提示动画「干瞪眼」。关掉屏幕之后不一会 Agora 就被杀后台了；后来亮着屏幕重试等了不知多长时间，模型终于吐字了，结果速度比 PPT 还慢，只有不到 3 tok/s，根本无法满足日常使用。

如果把上下文大小调高，比如 65536，那么 Agora 就会占用更大的内存（上下文越大，需要预留的内存也就越大），结果不一会内存占用飙升，触发了 ColorOS 的保护机制，强行终止了 Agora。看来仍然没办法满足日常使用啊。

最大的欠缺：缺少详细调优功能

从上面这个测试结果不难看出，v2.2.0 版本的 Agora 对本地模型的优化非常不到位。

Agora 运行 GGUF，用的是 llama.cpp，但并没有提供相关设置参数，因此用户无法自行根据设备情况来测试和调优 llama.cpp。对于我的一加13，若允许调节，我可以进行以下设置：

  • 明确使用 OpenCL 后端（这是专门为高通骁龙 SoC 优化的后端）；
  • 尝试不同的 -ngl （将模型卸载到 GPU 的层数），看看哪个值的内存占用恰好合适；
  • 启用 Fast Attention （-fa on），提升部分模型的推理效率。

同时，Agora 里的 llama.cpp 版本号也没有显示在「关于」界面中，更不能像 Jan 那样支持自定义 llama.cpp 版本。作者就这么想让一套默认设置（或者他自己手上设备的设置）「吃遍」所有 Android 设备，结果就只能是不兼容。

Agora 可能是目前唯一一款支持快捷配置本地模型的开源聊天工具了，这可以说是它的「杀手级」特性，可惜目前做得还不到位。我觉得，Agora 要想该特性真正发挥威力，就需要允许用户自行调节 llama.cpp 的参数。

写在最后

Agora 的诞生，弥补了 Android 平台缺少开源、易用、好用的 BYOK LLM 聊天工具这一空白，更弥补了开源聊天工具体验跟不上商业 AI 客户端（如 Kimi、豆包、ChatGPT 等客户端）的遗憾。MiMo 等尚未提供客户端的 LLM，也可以通过 Agora 访问，让你随时随地与大模型连结。

初上手时 Agora 就立刻吸引了我，现在我更是离不开它，每天都享受着它与 MiMo 配合时展现的强大功能特性，沉浸于它在聊天上的顺滑、极致体验，尤其是在「本地沙盒」加持下的会话内终端调用能力（堪比一个小型的、位于会话中的 Agent）。现在它基本取代了手机上其他的 AI 客户端，成为了我的好搭档。当然，如果它未来能改进本地模型体验，我还愿意把自己喜欢的模型（如 Gemma4、Qwen3、南北阁 4.2）搬到手机里，离线时也能享受 Agora 的强大。

如果你在通过 API 调用你喜欢的大模型，希望它们能像 Kimi 等商业 AI 客户端那样用着顺手，那 Agora 就是为你而来的。相信我，Agora 不会让你失望。
