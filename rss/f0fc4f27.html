第2周：搜索流量开始来了——小程序SEO的收录机制与排名调优实录

摘要

第1周跑完冷启动后，第2周的核心任务是验证搜索基建是否生效，并针对收录延迟、排名波动做调优。本文从微信小程序的索引机制出发，结合 sitemap.json 配置和后台关键词策略，拆解搜索流量从0到1的实操路径，附带可复用的排查清单。

前言

上周写了一篇7天冷启动的执行方案，有人问：关键词配了，小程序码也发了，但搜一搜里还是搜不到，是不是方案有问题？

不是方案有问题，是时间没到。

微信小程序的搜索收录存在延迟。刚发布或刚配置关键词的小程序，通常需要1-2天才能被搜索到。第1周配的关键词，第2周才是验证效果的时候。

这篇文章聚焦第2周的核心任务：确认搜索流量是否真的进来了，以及如果没进来，问题出在哪。

一、先理解微信小程序的搜索索引机制

在排查“为什么搜不到”之前，需要知道微信是怎么决定收录哪些页面的。

微信通过爬虫对小程序页面内容建立索引。爬虫访问时携带特定的 user-agent：mpcrawler，scene 值为 1129。当用户搜索词触发索引时，对应页面才可能出现在结果中。

关键点：如果爬虫发现页面数据与真实用户看到的不一致，该页面不会进入索引。

这意味着两件事：

  1. 动态渲染的页面可能抓不到。如果你的商品详情页依赖大量异步请求，爬虫访问时拿到的是空壳，收录就会失败。
  2. sitemap.json 的配置决定了哪些页面允许被索引。默认情况下，没有 sitemap.json 时所有页面都被允许索引。但如果你在开发阶段为了调试方便关闭了某些页面的索引，忘记打开，搜索流量就进不来。

检查方式很简单：在开发者工具中，sitemap 的索引提示默认是开启的。控制台会显示当前页面是否被索引。如果被 disallow 了，控制台会给出提示。

二、第2周第一件事：验证收录状态

2.1 直接搜

用微信搜一搜，搜你的完整小程序名称。如果能搜到，说明基础收录没问题。如果搜不到，先确认发布时间是否超过48小时。

2.2 搜关键词

搜你第1周配置的核心关键词。这里有一个常见误区：搜到了小程序名称，不等于搜到了关键词。

名称匹配和关键词匹配是两套逻辑。名称的权重最高，前缀匹配的优先级也高。但关键词的生效需要更长时间，且受小程序整体质量影响。

根据微信官方说明，自定义关键词提交后审核需要7个工作日，审核通过后也不是一一匹配的关系。所以第2周搜不到关键词是正常的，不代表配置错了。

2.3 看后台数据

小程序后台的“搜索”数据模块会展示搜索来源的访问量。如果第1周配置了关键词，第2周这里应该有非零数据。如果连续几天都是0，才需要排查配置问题。

三、如果收录了但排名靠后，调什么

假设第2周能看到搜索流量了，但关键词排名在第5页开外，用户翻不到你。这时候需要动的是用户行为数据。

微信搜索的排序算法中，用户反馈的权重很高。点击率、停留时长、跳失率、复访率，这些指标直接影响排名。一个被验证有效的做法是引导用户主动搜索进入，而不是只靠扫码。

具体操作：在社群话术或线下物料中，把“扫码进入”改成“微信搜‘你的小程序名’领券”。搜索进来的用户意图明确，点击后的停留和转化行为质量更高，这些数据会反向提升搜索排名。

另一个容易被忽略的点是首屏加载速度。微信搜索对首屏加载有明确要求，控制在3秒内，该项占搜索权重的15%左右。如果你的小程序首页加载偏慢，搜索排名会被拖累。检查一下首页的图片是否用了 WebP 格式、是否走了 CDN、有没有不必要的同步请求。

四、内容承接页的收录优化

第1周提到，用户搜关键词进来后应该落到一个内容页而不是首页。第2周需要确认：这个内容页本身是否被索引了。

如果内容页是动态生成的（比如根据关键词参数渲染不同内容），爬虫可能抓取不到。优化方式是：

// 确保内容页在 onLoad 时同步渲染核心文本，不要等异步请求
Page({
  data: { content: '' },
  onLoad(options) {
    // 从本地缓存或同步数据源读取，确保首屏有可索引的文本
    const cached = wx.getStorageSync('recipe_' + options.id);
    if (cached) {
      this.setData({ content: cached });
    }
  }
})

同时检查 sitemap.json，确认内容页路径没有被排除：

{
  "rules": [{
    "action": "allow",
    "page": "pages/content/detail"
  }]
}

如果内容页依赖 URL 参数区分不同内容，可以在 sitemap.json 中用 params 和 matching 做优先级配置，让带关键参数的页面优先被索引。

五、第2周的数据观察重点

不要只看“搜索来了多少人”，要看搜索来源的转化质量。

如果搜索来源的停留时长明显低于分享来源，说明内容页和搜索词不匹配。用户搜“减脂食谱”进来，看到的却是商城首页或一个不相关的活动页，他会立刻退出。这时候要回去检查关键词和落地页的对应关系。

另一个观察点是关键词的曝光-点击比。后台能看到哪些关键词带来了曝光，但点击率低的关键词要么是排名太靠后（用户没翻到），要么是标题/简介没有吸引力。后者可以通过优化小程序简介的前30字来改善，把核心卖点和关键词自然嵌入。

六、第2周不该做的事

别频繁改小程序名称。 名称每月修改不超过1次，频繁改名会被算法判定为不稳定，清零历史累积的权重。第1周如果已经改过，第2周不要再动。

别刷搜索点击。 微信对异常搜索行为有识别机制，刷点击一旦被判定，轻则降权，重则屏蔽搜索入口。冷启动阶段的搜索流量增长应该是缓慢的、真实的。

别指望关键词立刻见效。 自定义关键词审核7个工作日，生效后也不是一一匹配。第2周没看到关键词流量，不代表配置失败。继续做用户行为数据，排名会慢慢上来。

第2周的核心不是“做更多”，而是验证和调优。

检查清单：

  • 搜完整小程序名称，确认基础收录
  • 检查 sitemap.json，确认内容页未被误排除
  • 对比搜索来源与分享来源的停留时长
  • 检查首屏加载是否在3秒内
  • 在社群/线下话术中增加“主动搜索”引导
  • 不改名、不刷量、不焦虑

搜索流量是慢变量。第2周能看到零星数据，说明方向对了；如果是0，先排查收录配置，再给一周时间。第3周再来看，曲线会不一样。
