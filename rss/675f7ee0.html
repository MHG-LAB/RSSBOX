让 Agent 读懂你的身体：数据处理篇


在上一篇文章《让 Agent 读懂你的身体：数据获取篇》中，我花了很大的篇幅讲清楚了第一个问题：Agent 怎样拿到数据。如果照着实践完，你大概率已经收获了一份存储了运动健康数据的 SQLite、Markdown 或 JSON 文件。

此时，大多数人大概就忍不住让 AI Agent 来帮忙分析一下文件了——

「Claude，这是我的健康运动数据，帮我做一下详细的分析。」

我自己起初也是这么做的。在简短的提问之后，Claude 就能生成一个精美的 HTML。上面有每个动作的训练趋势、恢复状态的图标以及按照日历排列的训练日历图等。信息排得很满，但研究一下就会发现，它除了好看，并没有什么用。

这就是问题所在——AI Agent 擅长描述，而如果想让它分析实际问题并给出建议，比如下一次训练该加多少重量，则需要用户自己对需求的判断与适当引导。

所以，在这篇文章中，我会根据我的实际经验，来详细回答后面的两个问题：拿到数据以后，怎样让它正确地处理？它给出的结论能信几分？

注：目前我这套方法只适用于辅助日常的运动训练，不建议用于排查身体的实际症状，也不应用于应对医疗情况。

怎样让 Agent 正确处理数据

我的整体方案

以我自己为例，我用：

  • Apple Watch 记录运动训练数据，包括有氧和抗阻训练；
  • Oura Ring 记录睡眠、夜间恢复以及日常活动数据；
  • 训记 App 专门记录抗阻训练的容量和组数（同时使用训记和 Apple Watch 不会重复计入运动数据）

其中，Apple Health 和 Oura 的数据都接进第三方服务 Freddy。它通过 Oura 的官方接口授权读取，所以 Oura 自己算出的准备指数（Readiness）等算法数据也能拿到。

接着，通过 Agent 预先写好的 Python 脚本，经 Freddy 和训记的 API 将数据拉取到本地，存进 SQLite 数据库。而体脂、体重这类低频指标和训练感受等，我会用文字或图片的形式直接发给 Agent，由它整理后录入数据库。

上述项目搭建在家里的 NAS 上，Python 脚本定时拉取最新的生理和训练数据；网页看板设置好端口，通过局域网地址就可以直接访问。

去健身房之前，我用手机或电脑通过局域网连上 NAS 触发任务。常规任务在网页看板上留有按钮，可以一键启动；复杂的任务则通过终端里的 CLI 工具对话进行。触发后，AI Agent 读取最新的身体数据和训练记录，先由两个「教练」给出动作、组数和重量建议，再由「循证教练」核查训练量和强度。最终由我自己确认后，将计划作为一条训练记录，通过 API 写进训记。

到了健身房，我只要打开训记照着计划练，并给每组动作备注余量和训练感受。这些内容最终会通过 API 回传给 AI，完成一次循环。

把这些环节串起来并不复杂。真正需要花心思的，是给 Agent 建立一套「行为规范」，让它稳定地分析已有的数据并输出建议。方法很简单，搞个 Skill 就行。

为什么不用现成 Skill

「不要重复发明轮子」是软件开发领域的至理名言。一般来说，我们应该先看看社区里已有的 Skill，如果它们可以覆盖需求，直接套用即可。

其中，Coach Paddy 相对最接近我个人的需求。它内置了数据接口，能够读取 Garmin、COROS、WHOOP 和 Apple Watch 的数据，力量训练数据可以选配训记的 API；记忆存在用户的 Obsidian 里，包括运动员档案、训练计划和每日生理数据等。它会给出准备度评分，用来决定当天全力、降级还是休息，也能提供训练计划、进行每周复盘，算是一套相对完整的解决方案。

Coach Paddy 还有个值得借鉴的机制：出现数据缺失时，准备度评分就会降级，替换为 1 到 5 分的主观精力评分。

我最终没有选择 Coach Paddy。首先，我不需要它的数据接口模块。而且它虽然自称支持多项运动，分析的重心却在耐力训练和赛事备战，有比赛信心分、比赛倒计时等功能，和我的应用场景不吻合。此外，项目的 Star 和 Fork 不多，说明实际效果可能验证不足。

其实，现有的 Skill 多多少少都有类似的问题。因为训练是一件很个人的事情：训练目标、关注的指标、可用的器械、作息习惯、运动体系等，人人都不一样，现成的 Skill 很难完美适配。同时，健康和训练类 Skill 的关注度普遍较低，我目前找到的最多也不过 200 多个 Star，使用反馈大都不足。

注：

  1. 统计时间为 2026.10.16；
  2. Stars 一栏中的「-」表示该 Skill 为项目的子文档，没有单独的 Star；
  3. 类型一栏是我的主观分类，仅供参考。

所以，如果你能接触到顶级模型（例如 Claude Fable 或 ChatGPT Astra 等），不如让 Agent 吸取现成 Skill 的可取之处，在此之上定制一个适配个人习惯的 Skill。

定制 Skill，最难也是最关键的一步就是把需求梳理清楚，然后制定详细的实施方案。我会先用 grill-me 技能把需求问清楚。它来自 Matt Pocock 的开源 Skill 仓库，作用是让 Agent 反过来向你提问：从粗略的想法出发，一直追问到形成确定而详细的结论。坏处就是有时候你会觉得，它怎么还有这么多问题。
