3-6 项目-图形版井字棋（上）

3-6 项目-图形版井字棋（上）

⏱ 本节预计用时：30分钟

本节意义：可以进一步体会model-view架构，初步理解状态机的思想，这些都是必用的。更别提你是在结合前两节学到的知识，给图形版井字棋搭骨架，这难道不是一件很爽的事情吗？

本节目标：理清这节只改 view 和 main、model 一行不动；能画出主菜单和空棋盘；用 Screen 这个枚举当"状态变量"控制界面切换；理解"一个界面对应一个状态，改状态就切界面"。

1 只改view、不改model

第二章（2-6）我们已经把井字棋拆成了 5 个文件：

code/6-4井字棋-多文件/
├── game.h     ← Model 头文件（类型定义 + 声明）
├── game.c     ← Model 实现（数据 + 规则）
├── view.h     ← View 头文件
├── view.c     ← View 实现（画界面）
└── main.c     ← 主控（安排流程）

这一节我们就照着 2-6 的样子，把界面换成图形。上一讲我们说过，井字棋从命令行版改成图形版，底层的逻辑完全没变，变的只是"界面"。 model 层里的board、currentPlayer、initBoard、checkWin 这些"数据 + 规则"不变，游戏规则不会因为换个界面就坏掉，所以model层的代码一个字母都不用动，需要重写的只有 view 和 main。

文件这一节动不动动了啥
game.h不动——（直接复制 2-6 的）
game.c不动——（直接复制 2-6 的）
view.h小改引入 raylib、加一个"当前界面"状态、加几个"判断点了哪里"的函数
view.c大改原来是一堆 printf，现在换成 raylib 的绘图
main.c大改原来"读数字选菜单"，现在"读鼠标点按钮"

直接上 view.h ：

后面的工作就是在view.c里把这些函数补全，然后在main.c里组织界面按想要的逻辑显示。

先设计界面，粗略确定每个矩形、每行字的位置，位置画出来不满意在这个基础上再改。

编译运行：

点 START 进入游戏界面，看到空棋盘和下方的 MENU 按钮。

点 MENU 回到主菜单，点 EXIT 退出。

回过头去看代码，你会注意到一个特别有意思的事情，界面一直在刷新，如果状态screen == SCREEN_MENU的时候就加载主菜单界面，如果状态screen == SCREEN_GAME的时候就加载游戏界面，在主菜单界面的时候（screen = SCREEN_MENU时）你可以点按钮，令screen = SCREEN_GAME，这样就切到游戏界面了，反之亦如是。

一个界面对应一个状态变量，状态变量改变则界面改变。要增加一个新的界面，只需要再增加一个状态变量，在更新阶段下加入别的状态变量怎么变成它，它怎么变成别人的逻辑，在渲染阶段下加入如果当前的状态变量是我，就渲染新界面的逻辑，就行了。

我们管这种编程设计的思想叫状态机。
