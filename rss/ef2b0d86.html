一文搞懂 LangGraph 分支、循环与状态持久化

上一篇我们搞定了 LangGraph 的线性流程编排和多 Agent 协作基础。这一篇深入 LangGraph 最核心的三个能力：条件分支、循环重试、状态持久化，最后再来一个硬核的 中断/恢复 实战。

一、条件分支：让工作流"会思考"

为什么需要分支？

线性流程只能 A → B → C 一路走到黑。真实场景中，Agent 需要根据输入决定走哪条路——用户问数学题走计算器，闲聊走对话，代码走 Code Interpreter。

LangGraph 用 addConditionalEdges 实现分支。

完整代码

import {
  Annotation, END, START, StateGraph
} from '@langchain/langgraph';


// ① 状态定义
const StateAnnotation = Annotation.Root(&#123;
  query:  Annotation(&#123; reducer: (_prev, next) => next, default: () => “” &#125;),
  route:  Annotation(&#123; reducer: (_prev, next) => next, default: () => “chat” &#125;),
  answer: Annotation(&#123; reducer: (_prev, next) => next, default: () => “” &#125;)
&#125;);


// ② 路由节点：判断输入类型
const router = (state) => &#123;
  const isMath = /[+-*/]/.test(state.query);
  return &#123; route: isMath ? “math” : “chat” &#125;;
&#125;;


// ③ 数学节点：用 eval() 计算表达式
const mathNode = (state) => &#123;
  try &#123;
    return &#123; answer: String(eval(state.query)) &#125;;
  &#125; catch &#123;
    return &#123; answer: “表达式无法计算” &#125;;
  &#125;
&#125;;


// ④ 对话节点
const chatNode = (state) => (&#123; answer: 你说的是：<span class="hljs-subst">$&#123;state.query&#125;</span> &#125;);


// ⑤ 编排
const graph = new StateGraph(StateAnnotation)
  .addNode(“router”, router)
  .addNode(“math”, mathNode)
  .addNode(“chat”, chatNode)
  .addEdge(START, “router”)
  .addConditionalEdges(“router”, (state) => state.route, &#123;
    math: “math”,
    chat: “chat”
  &#125;)
  .addEdge(“math”, END)
  .addEdge(“chat”, END)
  .compile();

流程图

graph TD;
    __start__([__start__]) --> router{router}
    router -->|route=math| math[math]
    router -->|route=chat| chat[chat]
    math --> __end__([__end__])
    chat --> __end__

执行过程

// 输入含数学符号 → 走 math 分支
await graph.invoke({ query: "1+2" });
// → router 判断: isMath=true → route="math"
// → mathNode: eval("1+2") = 3
// → { query:"1+2", route:"math", answer:"3" }


// 普通文字 → 走 chat 分支
await graph.invoke(&#123; query: “你好” &#125;);
// → router 判断: isMath=false → route=”chat”
// → chatNode: answer=”你说的是：你好”
// → &#123; query:”你好”, route:”chat”, answer:”你说的是：你好” &#125;

面试高频问：addConditionalEdges 和 addEdge 有什么区别？

API作用决定时机
addEdge(from, to)固定连线，永远走 to设计时确定
addConditionalEdges(from, fn, map)运行时根据状态动态选路运行时决定

一句话：addEdge 是"写死的路"，addConditionalEdges 是"到路口再决定"。

二、循环重试：让工作流"会坚持"

为什么需要循环？

Agent 执行不是一次就成功的——API 调用超时、LLM 输出格式不对、用户确认不通过……都需要重试机制。

LangGraph 用 addConditionalEdges 让节点回到自己，形成循环。

完整代码

const StateAnnotation = Annotation.Root({
  tries:   Annotation({ reducer: (_prev, next) => next, default: () => 0 }),
  ok:      Annotation({ reducer: (_prev, next) => next, default: () => false }),
  message: Annotation({ reducer: (_prev, next) => next, default: () => "" })
});


const attempt = (state) => &#123;
  const tries = state.tries + 1;
  const ok = tries >= 3;  // 第3次才算成功
  return &#123;
    tries,
    ok,
    message: ok ? 第<span class="hljs-subst">$&#123;tries&#125;</span>次成功 : 第<span class="hljs-subst">$&#123;tries&#125;</span>次失败
  &#125;;
&#125;;


const graph = new StateGraph(StateAnnotation)
  .addNode(“attempt”, attempt)
  .addEdge(START, “attempt”)
  // 条件边：失败 → 回到自己，成功 → 结束
  .addConditionalEdges(“attempt”, (state) => state.ok ? “done” : “retry”, &#123;
    retry: “attempt”,
    done: END
  &#125;)
  .compile();

流程图

graph TD;
    __start__([__start__]) --> attempt[attempt]
    attempt -->|ok=false| attempt
    attempt -->|ok=true| __end__([__end__])

执行过程

await graph.invoke({ tries: 0 });
// 第1轮: tries=1, ok=false → "第1次失败" → 回到 attempt
// 第2轮: tries=2, ok=false → "第2次失败" → 回到 attempt
// 第3轮: tries=3, ok=true  → "第3次成功" → END
// → { tries:3, ok:true, message:"第3次成功" }

面试高频问：分支和循环用的是同一个 API？

是的，都是 addConditionalEdges。

区别在于 map 里映射的目标：

// 分支：映射到不同节点
{ math: "math", chat: "chat" }


// 循环：映射回自己
&#123; retry: “attempt”, done: END &#125;

一句话：分支是"走哪条路"，循环是"要不要重来"，底层同一个 API，映射目标不同。

三、状态持久化：让工作流"有记忆"

没有持久化的问题

每次 graph.invoke() 状态都从默认值开始，相当于每次都失忆。

第1次调用 → visitCount=0 → 结果1
第2次调用 → visitCount=0 → 结果1   ← 又从头开始了
第3次调用 → visitCount=0 → 结果1

MemorySaver：一行代码加记忆

import { MemorySaver } from '@langchain/langgraph';


const checkpointer = new MemorySaver();   // 内存保存器
const app = graph.compile(&#123; checkpointer &#125;);

加上 checkpointer 后，每次 invoke 结束自动保存状态快照，下次同一会话调用时自动恢复。

完整代码

import {
  Annotation, END, START, MemorySaver, StateGraph
} from '@langchain/langgraph';


const StateAnnotation = Annotation.Root(&#123;
  visitCount: Annotation(&#123; reducer: (_prev, next) => next, default: () => 0 &#125;),
  message:    Annotation(&#123; reducer: (_prev, next) => next, default: () => “” &#125;)
&#125;);


function recordVisit(state) &#123;
  const visitCount = state.visitCount + 1;
  const message = visitCount === 1
    ? “这是你在本会话里第1次进入。”
    : 这是你在本会话里<span class="hljs-subst">$&#123;visitCount&#125;</span>次进入;
  return &#123; visitCount, message &#125;;
&#125;


const graph = new StateGraph(StateAnnotation)
  .addNode(“recordVisit”, recordVisit)
  .addEdge(START, “recordVisit”)
  .addEdge(“recordVisit”, END);


const checkpointer = new MemorySaver();
const app = graph.compile(&#123; checkpointer &#125;);

多用户会话隔离

const user1 = { configurable: { thread_id: "用户-小张" } };
const user2 = { configurable: { thread_id: "用户-小李" } };


await app.invoke(&#123;&#125;, user1);  // &#123; visitCount:1, message:”这是你在本会话里第1次进入。” &#125;
await app.invoke(&#123;&#125;, user1);  // &#123; visitCount:2, message:”这是你在本会话里2次进入” &#125;
await app.invoke(&#123;&#125;, user1);  // &#123; visitCount:3, message:”这是你在本会话里3次进入” &#125;
await app.invoke(&#123;&#125;, user2);  // &#123; visitCount:1, message:”这是你在本会话里第1次进入。” &#125;
//                        ↑ 小李是独立会话，从头开始

thread_id 就是会话标识——不同用户、不同对话，状态完全隔离。

面试高频问：MemorySaver 和数据库存储有什么区别？

MemorySaver数据库存储
存储位置进程内存SQLite / Redis / PostgreSQL
重启后丢失保留
适用场景开发调试、无状态要求生产环境、需要持久化
实现方式LangGraph 内置需要换 Checkpointer 实现

生产环境把 MemorySaver 换成 SqliteSaver 或 RedisSaver，API 完全一样，只需改一行 import。

四、中断与恢复：让工作流"会等待"

这是 LangGraph 最强的能力之一——让图暂停，等人类输入后再继续。

场景：转账确认

import {
  Annotation, END, START, StateGraph,
  Command,        // 用于恢复时传入数据
  interrupt,      // 中断函数
  MemorySaver
} from '@langchain/langgraph';
import { createInterface } from "node:readline/promises";


const StateAnnotation = Annotation.Root(&#123;
  actionSummary: Annotation(&#123; reducer: (_prev, next) => next, default: () => “” &#125;),
  userInput:     Annotation(&#123; reducer: (_prev, next) => next, default: () => “” &#125;)
&#125;);


// 展示转账信息
const showTransfer = () => (&#123;
  actionSummary: “向张三转账 $100”
&#125;);


// 中断：等待用户确认
const waitConfirm = (state) => &#123;
  const text = interrupt(&#123;
    hint: “终端里输入[确认]或者备注后回车，图才会继续”,
    actionSummary: state.actionSummary
  &#125;);
  return &#123; userInput: String(text) &#125;;
&#125;;


const graph = new StateGraph(StateAnnotation)
  .addNode(“showTransfer”, showTransfer)
  .addNode(“waitConfirm”, waitConfirm)
  .addEdge(START, “showTransfer”)
  .addEdge(“showTransfer”, “waitConfirm”)
  .addEdge(“waitConfirm”, END)
  .compile(&#123; checkpointer: new MemorySaver() &#125;);

流程图

graph TD;
    __start__([__start__]) --> showTransfer[showTransfer]
    showTransfer --> waitConfirm[waitConfirm]
    waitConfirm -.->|interrupt: 等待输入| waitConfirm
    waitConfirm --> __end__([__end__])

执行过程：两阶段调用

const config = { configurable: { thread_id: "interrupt-demo" } };


// 第一阶段：执行到 interrupt 自动暂停
const paused = await graph.invoke(&#123;&#125;, config);
console.log(“待你确认:”, paused.interrupt?.[0]?.value);
// → “终端里输入[确认]或者备注后回车，图才会继续”


// 此时图的状态已保存到 MemorySaver，进程可以退出


// 第二阶段：用户输入后，用 Command 恢复执行
const rl = createInterface(&#123; input: process.stdin, output: process.stdout &#125;);
const line = (await rl.question(“> “)).trim();
await rl.close();


const done = await graph.invoke(new Command(&#123; resume: line &#125;), config);
console.log(“done:”, done);
// → &#123; actionSummary:”向张三转账 $100”, userInput:”确认” &#125;

面试高频问：interrupt 和普通暂停有什么区别？

interrupt普通暂停
状态保存自动保存到 checkpointer丢失
恢复方式new Command({ resume })无法恢复
多次中断支持，状态链式保存不支持
生产可用是，支持数据库持久化仅开发调试

一句话：interrupt 是 LangGraph 的"人工审批节点"——暂停时状态自动存档，恢复时用 Command 传入人类决策，整个过程可审计、可持久化。

五、核心概念总结

API 速查表

API作用类比
Annotation.Root({})定义状态结构数据库建表
StateGraph创建流程编排器画流程图
.addNode(name, fn)添加处理节点流程图里的方框
.addEdge(from, to)固定连线"做完 A 做 B"
.addConditionalEdges(from, fn, map)条件分支/循环"如果...就..." / "重来"
.compile({ checkpointer })编译 + 注入持久化编译 + 配置运行时
interrupt({})中断等待人类输入审批暂停点
new Command({ resume })恢复中断的图传入审批结果
thread_id会话隔离标识用户 session ID

三种模式对比

模式核心 API典型场景
分支addConditionalEdges → 不同节点输入分类、意图路由
循环addConditionalEdges → 回到自己重试、轮询、等待条件满足
持久化MemorySaver + thread_id多轮对话、断点续传、多用户
中断interrupt + Command人工审批、确认操作

面试万能回答

LangGraph 的核心是有状态的图编排。用 Annotation 定义共享状态，用 StateGraph 组织节点和边，用 addConditionalEdges 实现分支和循环，用 checkpointer 实现状态持久化和多会话隔离，用 interrupt 实现人类审批节点。它和 LangChain 共享底层基础设施，但解决了 LangChain 解决不了的复杂流程控制问题。

六、给你的代码加记忆，就一行的事

// 没有记忆
const app = graph.compile();


// 有记忆（开发环境）
const app = graph.compile(&#123; checkpointer: new MemorySaver() &#125;);


// 有记忆（生产环境）
import &#123; SqliteSaver &#125; from ‘@langgraph/checkpoint-sqlite’;
const app = graph.compile(&#123; checkpointer: new SqliteSaver() &#125;);

记住这个模式，所有 LangGraph 工作流都能一键升级为有记忆的版本。
