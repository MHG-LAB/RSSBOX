关于展示性网页+个人博客重构, 从 Halo 和 Wordpress 中摆脱出来, 意外发现很有意思的动静态结合的方法

woodchen:

一个从 wordprss 迁移, 一个从 halo 迁移, 由于场景不同, 写了两套, 但基本逻辑类似.

迁移理由

  1. wordpress 的速度可以优化, 但是扩展不是很方便, 不像私有仓库, push, deploy 自动化
  2. halo 的 java 内存占用高, 并且又去搞商城, 还有这种奇怪的变动让我文章页面错误好几周(有部分文章以前从 typecho 迁移到 halo, 文章 url 没变) 升级 2.22.x 后, slug 为四位数, 比如 1207 时, 访问文章, 变成 文章归档 页面
  3. 自定义扩展方便, 多语言, ai 自动翻译, ai 优化 seo, mcp.

非纯静态理由

  1. 需要 MCP 给 agent 去发
  2. 需要接入 ai 模型做文章翻译, SEO 描述, 自动做 ai 任务队列
  3. 需要动态改内容, 并且内置 indexnow
  4. 阅读数动态统计什么的
  5. 方便

非纯动态理由

  1. 速度
  2. ai 方便抓取和阅读
  3. 没有必要

方法

  1. 后端 go
  2. 管理端动态网页, 可以绑定其他域名或放 url 路径

当内容变更, go 来负责next build, 构建静态网页, 然后可以通过下面两种方式去分发.

  1. 另起容器, 共享前端网页卷, 如果有需要后端 api, 可反代几个动态接口到 后端 build 容器

  2. 直接放一个容器, go-web-utils/nextstatic 来负责处理 next 静态文件路由

效果还不错.
