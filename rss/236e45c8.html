在Finch用了62亿词元，我认为这是新一代Agent工具之神

老朋友都知道，我喜欢推荐好东西，很多朋友都在我的种草下，开始尝试和使用一些不错的软件，工具等。

今天分享推荐的这个东西，叫做 Finch，中文译名 芬奇，中文外号 小灵雀， 其形象就是一只可爱的小鸟，坊间也称呼为 小鸟Agent/小鸟AI，网址 finchwork.app/zh。

它是目前大火的 Agent 工具方向，与 Codex 和 ZCode 是同类产品。

我用过市面上几乎所有的 Agent 工具，在被 Codex 的卡顿烦的不行的情况下，试用了一下国产的 ZCode，被其流畅的体验所折服，日夜兼程用了18亿 Token。

并不遗余力地在 ZCode 飞书交流群，反馈了几十个建议。

比如这个红线标记处，显示 提供商 + 模型名 的功能，就是我提了几次建议后，官方最终采纳并实现的。

好工具，好产品，我愿意深度使用，并提供真实使用后的反馈和建议。

但使用过 Finch 后，我彻底爱上了，这就是我梦寐以求的 Vibe Coding 工具，深度使用了一个月，消耗了 62亿 Token 后，我用这篇文章，把它推荐给你。

写这篇文章的时候，我尝试回忆一下，我到底是怎么第一次安装 Finch，怎么第一次使用的，我发现我已经记不清了。

所以，我希望，如果你也像我一样爱上了 Finch，那么你能够回忆起，并找到我的这篇种草文章。

快

快，非常地快！

这是我对 Finch 的一印象。

虽然这是一个基于 Electron 开发的应用，但卡顿感几乎感受不到，这是其他所有同类工具都不具备的。

在没用 Finch 之前，我以为 ZCode 已经是 闪电侠 了，没想到 Finch 居然是 曹操，你不管再宇宙何处，说曹操，曹操就到！。

当然，有点夸张的修辞，但在我目前用过的所有同类工具中，Finch 的快，是无与伦比的，是 No.1 的。

如上动图，我在不同的会话切换，聊天内容是瞬间出现的，没有任何卡顿发生。

要知道，我不喜欢创建新会话，只有偶尔有个临时问题在当前对话创建个分支，用完即删。

所以，我把我的主要会话，命名为 主线任务，这是我好几天，甚至好几周的对话，多的甚至有上百条，几百条对话。

而我每天的Token消耗，平均都在 3亿-5亿 左右，最高的一次是 2026年9月11 日的 11.5亿，可见对话次数之多，上下问数据之大。

但不管你对话多少，Finch 切换会话的时候，聊天窗口都是瞬间显示的，感受不到卡顿的存在，我非常在乎这个，天下武功，唯快不破。

空间级 Agents.md

这是我比较关注的第二个特性。

如图，我所有的开源项目，自己的网站，后端接口，VSCode扩展，桌面应用，小程序，Skills等等，全部都在一个仓库待着，用 Monorepo 的方式管理和组织。

因为我不想打开多个窗口，在多个编辑器跳来跳去，令人烦不胜烦。

但这样有个问题，如果我要开发某一个子项目，那么项目很多，很容易受到其他项目，其他 Agents.md 的影响，反正几个月之前是这样的，现在随着AI的进化，问题改善了不少。

但 Finch 专门为这个问题，提供了空间级的约束。

举个例子，如上图，我把 desktop 目录作为 工作区，然后在该 工作区 创建 空间，有意思的来了。

如上图，为了保证不同空间项目在开发的过程中的一刀见血，我会在 工作区 的 Agents.md 文件中，把所有桌面应用应该共同遵守的规范写好。

同时，也会给单个项目，写好它自己的 Agents.md 规范。

这样，多层保险之下，我的 Vibe Coding 过程非常精准，日常处理的问题更多的是架构设计和具体实现的调整。

由于 desktop 下的桌面应用有自己的编译，构建，测试流程，所以在 空间级Agents.md 和 工作区级Agents.md 的双重约束下，整个Vibe Coding过程非常流畅，爽快无比。

而且一切，都源于 Finch 对不同层级的 Agents.md 指令的约束和遵从，这是很多 Agents.md 工具都不具备的微操细节。

这个功能唯一有点遗憾的就是，不会自动加载仓库级 Agents.md，所以我得在每个 空间级Agents.md 头部加上一句提醒：记得去看仓库级Agents.md。

不过我今天已经反馈了，后续全局级，仓库级，工作区级，空间级 Agents.md 的加持下，体验和准确度又能更上一个台阶！

小程序

小程序是 Finch 的一个杀手功能，可以理解为 Skills 的升级版。

我们可以通过小程序，来改造 Finch。

可以通过 网页助手 小程序，在对话框下面显示网页操作设置和状态查看，比起 Skill 后台黑盒直观不少。

也可以通过 写字 小程序，在侧边栏查看和编辑 Markdown 文件。

甚至连终端，都是 可插拔 的。

这给了 Finch 极大的灵活性和扩展性，与 VSCode 的插件非常相似，需要什么，都可以自己创造。

目前我看在灵活性和可插拔层面，DSH 也不逞多让，但我觉得 DSH 唯一的问题就是 太过于灵活。

如果用两个闻名已久的效率工具来对比，我觉得 Finch 类似 Utools，而 DSH 类似 Quicker。

曾经不理解 小程序 和 Skills 的区别，简单来说就是，小程序的功能是固定的，你调用100次，100次的结果是可靠的，稳定的。

而 Skills，它依赖于大模型的智力水平，你把 Skill 写得再清楚，使用的时候也不能 100% 保证 AI 一定就照做，有可能会开点小差。

所以，我非常喜欢 Finch 的小程序功，连它的桌宠，都是小程序实现的，所以 Finch 的内核非常稳定，强大，运行轻量，快速。

记忆

Finch 是一个越用越聪明的 Agent 工具。

它会自动根据日常使用，总结并提炼记忆，随着使用的时间增长，记忆也会进一步增强。

以前犯过的错误，踩过的坑，在对话过程中提到的一些规范，解决问题的过程中获得的经验，都有可能会记录到它的 记忆 中。

这样，我们就能在不断的使用中，获得一个越来越懂我们，越来越聪明，越来越好用的 Agent 工具了。

写在最后

高强度用了几个月 AI，每天都沉浸在高效的 Coding 中，文章也写得更少了。

AI 能给我们进行文章润色，但个人的体验，感受，想法，AI 是无法精准地表达出来的，更不会配这么多截图示例。

这是一次消耗了 62亿 Token 后的种草和推荐，全文手写无AI，无润色，真心推荐，希望助力诸君，走上 Vibe Coding 的巅峰！
